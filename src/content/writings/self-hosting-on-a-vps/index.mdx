Some time ago I purchased a VPS (Virtual Private Server) because I needed a server to host some web projects and also some cool services like a password manager or an ad blocker. This post explains the configuration of the server and also some concepts about the services I have running on it. Later on in the services section you'll also find a link to my Github repository where you can find the configuration files for all the services I mention here, but for now let's just start with the basics.

## 1. Choosing the Provider, Machine and OS

First step was choosing the provider and the machine to purchase. I chose the cheapest one you can get from Hetzner, you can check their available machines [here](https://www.hetzner.com/cloud/cost-optimized).

As for the operating system, I'm running Ubuntu 24.04.3 LTS.

Actually, when I first purchased the machine, I installed [Coolify](https://coolify.io/) on it. It's an open-source & self-hostable alternative to services like Vercel and Netlify.

But recently I ditched Coolify in favour of managing everything directly with Docker and Docker Compose. Coolify is great, but it abstracts a lot of what's actually happening under the hood. I wanted to actually understand container networking, reverse proxies, etc. And honestly, even though I know I'm still just getting started, I would say I have learnt a few things since then.

## 2. Securing the Server

Before running any services, I took some steps to secure my server.

#### 1. User Management

Created a non-root user with `sudo` privileges and migrated my SSH keys with permissions `700` for the `.ssh` directory and `600` for the `.ssh/authorized_keys` file.

#### 2. SSH Hardening

Edited `/etc/ssh/sshd_config` to explicitly disable `PermitRootLogin` and `PasswordAuthentication`. This ensures only key-based authentication is allowed for the non-root user.

## 3. Container Engine, Reverse Proxy and VPN

#### [Docker](https://docs.docker.com/)

Installed Docker Engine and Docker Compose, added my user to the `docker` group, and created a network called `proxy-network` to route requests to the containers.

I used Docker to run each app in its own isolated container. With this approach I needed a reverse proxy to route requests to the right containers. That's where Traefik comes in.

### [Traefik](https://traefik.io/traefik/)

A reverse proxy is more or less like a receptionist for your server. Instead of opening a dozen different ports for a dozen different apps, only Traefik listens to requests on ports 80 and 443 and then routes them to the appropriate container.

I set it up with the Cloudflare API to perform a DNS Challenge to automatically renew Let's Encrypt SSL certificates.

### [Tailscale](https://tailscale.com/)

Tailscale is a mesh VPN built on top of the WireGuard protocol that adds some really cool features that make it very convenient. Here are a couple of those conveniences:

**Keep my private services hidden:** Because of the P2P mesh network, known as tailnet, when I create subdomains in Cloudflare for my tools, I can point them to my server's IP address on the tailnet (e.g. `100.x.x.x`) instead of its actual public IP. This essentially means my services are only accessible through devices that are connected to the tailnet. If you try and type, for example `syncthing.bpcosta.com` in your browser, it won't resolve to anything.

**SSH-ing into my VPS:** Tailscale SSH eliminates the need to manage SSH keys. Instead of generating SSH keys for every device and adding them to `~/.ssh/authorized_keys`, Tailscale uses my tailnet identity to authenticate. I don't have a lot of devices in my tailnet, but if needed you can use ACLs to specify which devices can SSH into a machine. You can read more about it [here](https://tailscale.com/docs/features/tailscale-ssh).

Tailscale was designed to be an always-on VPN, so I usually keep it on all the time. The traffic is always routed through the device I'm using, so I don't have to worry about it exiting through my VPS, unless I explicitly toggle the option to use it as an exit node (or any other device).

## 4. My Tool Stack

With the base configuration and security done, I started installing my tools and services. All the `docker-compose.yaml` files for everything below are available in my [GitHub repository](https://github.com/bpcosta1/vps-config).

### [Vaultwarden](https://github.com/dani-garcia/vaultwarden)

Vaultwarden is essentially a self-hostable version of [Bitwarden](https://bitwarden.com), compatible with all official Bitwarden clients like the browser extension and mobile app.

I actually switched from Bitwarden to Vaultwarden not because I wanted to self-host it, but because it unlocks certain features that are paid in the original Bitwarden.

### [AdGuard Home](https://github.com/AdguardTeam/AdGuardHome)

AdGuard Home is a network-wide DNS sinkhole. The way I have it set up, my Tailscale network uses the VPS as its DNS server so every device connected to the VPN benefits from the filtering.

### [Syncthing](https://syncthing.net/)

Syncthing is a decentralized, peer-to-peer file synchronization tool. I use it mostly to keep my [Obsidian](https://obsidian.md) vault synced across my phone and laptop.

### [Termix](https://github.com/lukegus/termix)

Termix is a web-based SSH client. Whenever I need to run something on the go, I just open my browser, connect through the VPN, and I have a terminal ready to use.

**Note:** I do have some other services running, but these are the ones I found more relevant. Anyways, if you're interested, you can check out my [repository](https://github.com/bpcosta1/vps-config) for all of the services configs.
